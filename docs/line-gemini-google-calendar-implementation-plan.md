# LINE x Gemini x Google Calendar 智能預約系統開發計劃書（甜蜜事務所版）

## 1. 專案願景
為「甜蜜事務所（Tammy’s Studio）」打造一個專業、溫暖且細膩的 LINE 自動化客服。
系統將透過 Gemini 1.5 Flash 分析對話意圖與情緒，並整合 Google Calendar 完成預約流程，讓顧客（特別是孕媽咪）在被理解與被照顧的情境中完成預約。

---

## 2. 技術架構
- **後端執行環境**：Google Apps Script（GAS）
- **AI 大腦**：Gemini 1.5 Flash（啟用 Function Calling）
- **通訊介面**：LINE Messaging API（Webhook）
- **數據中心**：Google Calendar API（空檔查詢、建立/更新/取消事件）

### 2.1 高層流程
1. 使用者在 LINE 發送訊息。
2. LINE Webhook 將事件送至 GAS `doPost(e)`。
3. GAS 解析訊息後，交給 Gemini 進行意圖判斷（諮詢 / 預約 / 改期 / 取消 / 價格詢問 / 孕期建議）。
4. 若需操作預約，Gemini 透過 Function Calling 請求工具函式。
5. GAS 呼叫 Calendar API 查詢可預約時段、建立預約或取消預約。
6. GAS 將結果組合成「甜蜜助理」口吻，回覆到 LINE。

### 4.4 專業衛教資訊（孕期）
#### 為什麼孕期要除毛
1. 減少感染：懷孕體溫高、分泌物增多，除毛可降低悶熱騷癢與異味，減少感染風險。
2. 方便清潔：肚子變大後私密處不易清潔，除毛可讓日常清潔更輕鬆。
3. 避免刮毛不適：若生產前由院方刮毛，術後粗硬毛髮常造成不適；熱蠟除毛後新生毛髮較細軟。

#### 預約時間建議
- 初步預約：滿 15 週以上且胎象穩定可開始。
- 中後期保養：建議 26-27 週、32-33 週各除一次。
- 最後產前預約：
  - 自然產：預產期前 10-14 天
  - 剖腹產：與醫師約定日前 5-7 天

### 4.5 預約規範與提醒
- 兩次除毛建議間隔超過 1 個月。
- 建議提前預約，如需取消請於前 3 天告知。
- 現場禁止攜帶寵物。
- 可攜伴（同空間，不介意即可）。
- 術後提醒：當天穿著寬鬆、避免悶熱與過度摩擦，以加速退紅。
- 預約完成需重複確認：**名字、日期、時段**。

## 5. 系統指令集與核心邏輯

### 5.1 預約成功確認模組（必做）
當預約成立後，AI 必須主動執行：
1. 重複客人名字、日期、時段。
2. 加上溫馨提醒：
   - 「當天請穿著寬鬆的衣服過來喔，這樣退紅速度會更快，也會更舒服喔。」
3. 若為孕媽咪，依孕週補充建議（15+ 週起可開始、26-27 週、32-33 週、產前建議時間）。

### 5.2 預約衝突邏輯
當目標時段客滿：
1. 查詢該時段後 **2 天內**可預約空檔。
2. 以「先同理、再建議」格式回覆。
3. 至少提供 2-3 個替代時段，並請客人選擇。

### 5.3 意圖分類（建議）
- 服務與價格詢問
- 店址與交通詢問
- 孕期衛教詢問
- 新增預約
- 改期
- 取消預約
- 預約狀態查詢
- 真人客服轉接（保留擴充）

## 6. 實作設計（GAS）

### 6.1 建議檔案結構
- `Code.gs`：`doPost(e)`、路由分派
- `line.gs`：LINE 驗證、回覆 API
- `gemini.gs`：Gemini 呼叫與 function call 解析
- `calendar.gs`：Google Calendar 查詢 / 建立 / 修改 / 取消
- `prompt.gs`：System Prompt 與 Knowledge Base（可抽離到 Script Properties）
- `config.gs`：環境變數、API Key、Calendar ID

### 6.2 Function Calling 介面（建議）
- `check_availability(date, timeRange, serviceType)`
- `find_alternative_slots(date, timeRange, serviceType, days=2)`
- `create_booking(name, lineUserId, serviceType, date, startTime, notes)`
- `reschedule_booking(bookingId, newDate, newStartTime)`
- `cancel_booking(bookingId, reason)`
- `get_booking_by_user(lineUserId)`

### 6.3 Calendar 事件資料格式（建議）
- 標題：`[甜蜜事務所] {姓名} - {服務項目}`
- 描述：
  - LINE UID
  - 孕週（若有）
  - 特殊備註
  - 建立時間
- 標籤：可用 `extendedProperties` 保存 `bookingId`、`isPregnant`、`gestationalWeek`

## 8. 對話流程（摘要）
1. **需求接收**：辨識諮詢或預約意圖。
2. **資訊補齊**：確認姓名、服務項目、日期、時段、是否孕期與孕週。
3. **時段檢查**：查詢 Calendar。
4. **結果分流**：
   - 可預約：建立事件並送出成功確認模組。
   - 不可預約：觸發衝突邏輯，提供替代時段。
5. **收尾提醒**：術後提醒 + 取消政策 + 可再詢問。

## 9. 資安與維運建議
- API 金鑰與 Token 全部存放於 Script Properties。
- Webhook 驗簽（LINE Signature）必做。
- 記錄關鍵操作 log（建議含 requestId、lineUserId、bookingId）。
- 設置錯誤回應降級：Gemini 故障時，回覆固定禮貌訊息並提供人工接手入口。
- 建議建立「測試用 Calendar」與「正式 Calendar」分離。
